# خطة التنفيذ المرحلية

الخطة التالية ترتيب تنفيذي مبدئي، والمدد تقديرية وليست تعهداً زمنياً. لا تنتقل أي مرحلة إلى التالية قبل اجتياز بوابة القبول.

## المرحلة 0 — تثبيت الأساس (أسبوع إلى أسبوعين)
- مراجعة جميع الملفات الحالية ومخطط SQL وملفات seed.
- إزالة القيم السرية الثابتة وتثبيت سياسة الأسرار.
- تثبيت إصدارات الأدوات وإضافة lockfiles.
- بناء CI وتشغيل build/analyze/test.
- اعتماد ERD وقواعد تسمية الجداول وعزل الفروع.
- اعتماد سياسة البيانات التجريبية وبيئة التطوير.

**بوابة القبول:** بناء Backend وFlutter ينجحان، مخطط قاعدة البيانات يطبق على قاعدة فارغة، ولا توجد أسرار أو بيانات تعريفية حقيقية في المستودع.

## المرحلة 1 — الهوية والموظفون والفروع
- تسجيل الدخول، تجديد الجلسة، الخروج وإدارة الأجهزة.
- المستخدمون والأدوار والصلاحيات الدقيقة.
- الشركات والفروع والأقسام والمسميات.
- ملفات الموظفين والوثائق والتاريخ الوظيفي.
- أرقام وظيفية متسلسلة ومضمونة ذرياً.
- تدقيق التغييرات الحساسة.

**بوابة القبول:** اختبارات RBAC وعزل الفروع، وعدم إمكانية قراءة أو تعديل موظف خارج النطاق المصرح.

## المرحلة 2 — التشغيل اليومي
- الورديات والجدولة والتبديل.
- الحضور والانصراف وطلبات التصحيح.
- سياسات الاستراحات القابلة لتعديل المدير المخول لها.
- سقف الخروج المتزامن والفترات المحظورة والفواصل.
- مؤقتات الاستراحة وأحداث WebSocket.
- المغادرات والاستئذانات.

**بوابة القبول:** اختبارات تزامن، وساعة خادم، وسجلات قابلة للتدقيق، وحالات انقطاع الشبكة.

## المرحلة 3 — الطلبات والتواصل والإشعارات
- محرك طلبات وموافقات متعدد المستويات.
- إعلانات وتأكيد قراءة ورسائل داخلية.
- تسجيل رموز الأجهزة وإدارة تفضيلات التنبيه.
- Push عبر FCM وAPNs وWeb Push حسب المنصة.
- إعادة المحاولة ومنع التكرار وقياس التسليم.

**بوابة القبول:** إثبات وصول الإشعارات والتصرفات المطلوبة والتطبيق مغلق، على أجهزة فعلية ومتصفحات مدعومة.

## المرحلة 4 — الموارد البشرية والمالية
- الإجازات والأرصدة والسياسات المعتمدة.
- الرواتب والسلف والبدلات والخصومات.
- الأصول والعهد والتدريب والتقييم.
- المخالفات والمكافآت وإنهاء الخدمة.

**بوابة القبول:** مطابقة حسابات مالية بعينات معتمدة ومراجعة مختص قانوني/موارد بشرية، وقفل الفترات وسجل تدقيق.

## المرحلة 5 — الإدارة والتقارير
- لوحات المشرف ومدير الفرع.
- لوحة الإدارة العليا متعددة الفروع.
- تقارير قابلة للتصفية والتصدير.
- مؤشرات الأداء والتنبيهات الإدارية.

**بوابة القبول:** تطابق الأرقام مع مصادرها، واحترام صلاحيات المستخدم ونطاق فروعه في كل تقرير.

## المرحلة 6 — الجاهزية والإطلاق
- اختبار اختراق ومراجعة صلاحيات.
- اختبارات ضغط وأداء واستعادة نسخ احتياطية.
- اختبار قبول المستخدم UAT في فرع تجريبي.
- مراقبة الأخطاء والسجلات والتنبيهات التشغيلية.
- تدريب الموظفين والمديرين ودليل تشغيل.
- نشر تدريجي وخطة رجوع Rollback.

**بوابة القبول:** توقيع اعتماد مالك النظام، إغلاق العيوب الحرجة والعالية، وتجربة استعادة ناجحة.

## ترتيب الأولويات
الأمان وعزل الفروع وصحة البيانات تسبق سرعة إضافة الشاشات. لا تُبنى وحدات الرواتب أو التتبع أو الإشعارات الجماعية قبل وجود الهوية والصلاحيات وسجل التدقيق.


## سجل بوابة المرحلة صفر

لا تعد المرحلة صفر منتهية بمجرد وجود الملفات. يجب إغلاق جميع البنود التالية بدليل قابل للمراجعة:

- [ ] تدقيق كل ملف إعداد وملف SQL وملف seed.
- [ ] فصل بيانات التطوير التجريبية ومنع تحميلها تلقائياً.
- [ ] اعتماد migrations مرقمة قابلة للتطبيق على قاعدة فارغة والترقية بأمان.
- [ ] تثبيت lockfiles لكل من Backend وFlutter.
- [ ] نجاح Backend build وlint وunit tests وintegration tests.
- [ ] نجاح Flutter analyze وwidget tests على بيئة CI.
- [ ] اعتماد المصادقة والجلسات وإبطالها وإدارة الأجهزة.
- [ ] تطبيق صلاحيات deny-by-default واختبار كل endpoint.
- [ ] تطبيق عزل الفروع في الخادم وقاعدة البيانات وWebSocket والتقارير والملفات.
- [ ] اختبار عدم تسرب بيانات فرع إلى مستخدم فرع آخر.
- [ ] إعداد health/readiness checks ومراقبة الأخطاء والسجلات.
- [ ] فصل إعدادات development وstaging وproduction وإثبات عدم وجود أسرار في Git.
- [ ] مراجعة أمنية قبل السماح بأي نشر.

لا يبدأ تنفيذ وحدات الأعمال على أنها جاهزة للإنتاج قبل إغلاق بوابة المرحلة صفر، ويمكن بناء وحدات تطويرية على فرع منفصل بشرط استمرار تطبيق ضوابط الأمان وعدم نشرها.
