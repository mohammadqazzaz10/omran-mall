# خط أساس الأمان

## حالة حرجة قبل أي نشر
- لا تضع أسراراً أو كلمات مرور أو مفاتيح Firebase أو مفاتيح S3 أو JWT داخل Git.
- القيم الموجودة في ملفات الإعداد السابقة كانت أمثلة ثابتة وليست أسرار إنتاج معتمدة؛ تم استبدالها بعناصر نائبة في `backend/.env.example`، كما أزيلت كلمات المرور الثابتة من Compose.
- إذا استُخدمت أي قيمة منشورة سابقاً فعلياً في بيئة حقيقية، فيجب تدويرها فوراً. حذفها من آخر نسخة لا يمحوها من تاريخ Git.
- لا ترفع ملف `.env` أو ملفات service-account أو شهادات APNs.

## الهوية والجلسات
- كلمات المرور تُخزن باستخدام Argon2id أو bcrypt بإعدادات مدروسة.
- Access token قصير العمر وRefresh token دوّار وقابل للإبطال.
- لا تُخزن كلمات المرور أو refresh tokens كنص صريح.
- فرض MFA على الحسابات الإدارية عند توفره.
- تحديد معدل محاولات الدخول وقفل/تأخير المحاولات المشبوهة.
- إدارة الجلسات والأجهزة وإبطالها.

## الصلاحيات وعزل الفروع
- Deny by default؛ لا صلاحية دون منح صريح.
- تحقق الخادم من الدور والإذن ونطاق الفرع في كل endpoint وكل WebSocket event.
- لا تثق في branch_id القادم من العميل أو header دون مطابقته مع عضوية المستخدم.
- تطبيق PostgreSQL Row-Level Security أو آلية مكافئة كطبقة دفاع إضافية، مع اختبارات تثبت عدم تسرب البيانات.
- لا تمنح SUPER_ADMIN أو صلاحية جميع الفروع إلا بتفويض موثق.
- التقارير والملفات المرفقة والتصدير تخضع لنفس نطاق العزل.

## حماية التطبيق والبيانات
- CORS بقائمة origins محددة؛ يمنع wildcard مع credentials.
- TLS إجباري خارج localhost.
- التحقق من المدخلات وقيود DTO، وتحديد حجم الملفات وأنواعها.
- تشفير النسخ الاحتياطية والملفات الحساسة أثناء النقل والتخزين.
- روابط الملفات الموقعة قصيرة العمر.
- عدم تسجيل كلمات مرور أو tokens أو بيانات شخصية حساسة في logs.
- Audit log append-only للعمليات المالية والإدارية والحضور والصلاحيات.
- سياسة احتفاظ وحذف للبيانات وفق موافقة الإدارة والقوانين المعمول بها.

## تشغيل آمن
- فصل development / staging / production.
- حسابات وقواعد بيانات منفصلة لكل بيئة.
- أقل صلاحية ممكنة لحساب قاعدة البيانات.
- نسخ احتياطي آلي واختبار استعادة دوري.
- فحص dependency vulnerabilities وsecret scanning في CI.
- لا بيانات موظفين حقيقية في seed أو fixtures.

## إشعارات الموقع والهاتف
- لا تعتبر WebSocket بديلاً عن Push عند إغلاق التطبيق.
- Web Push يتطلب HTTPS وService Worker واشتراك Push صالحاً.
- Android يستخدم FCM، وiOS يستخدم APNs عبر إعدادات Apple الصحيحة.
- لا تضع بيانات حساسة في نص الإشعار؛ اجعل التفاصيل خلف تسجيل دخول.
