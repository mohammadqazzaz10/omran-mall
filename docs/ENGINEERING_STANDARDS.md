# معايير التطوير

## تقسيم المستودع
- `backend/`: NestJS API، الوحدات، الخدمات، الحراس والاختبارات.
- `client/`: Flutter Android/iOS/Web.
- `database/`: ERD، مخططات SQL، seeds، وترحيلات مرقمة.
- `docs/`: قرارات المعمارية والمتطلبات وخطط التشغيل.
- `.github/`: قوالب المراجعة وفحوص الجودة.

## Backend
- NestJS + TypeScript مع وحدات مستقلة لكل مجال.
- Controller رفيع، business logic داخل service/use-case، وطبقة persistence واضحة.
- DTO للتحقق من كل المدخلات؛ لا تمرر request body مباشرة إلى SQL/ORM.
- استخدام معاملات DB للعمليات المركبة.
- توحيد شكل أخطاء API وPagination وFiltering.
- إصدار API تحت `/api/v1` وتوثيق OpenAPI.
- WebSocket events موثقة ومحمية ومحددة بنطاق الفرع.
- لا تضع منطق الرواتب أو الوقت أو الصلاحيات داخل Controller.

## Flutter
- Flutter/Dart، Riverpod لإدارة الحالة، GoRouter للمسارات.
- تقسيم feature-first: كل ميزة تحتوي presentation/application/domain/data حسب الحاجة.
- فصل DTO/API models عن domain models.
- التخزين الآمن للرموز، وعدم حفظ أسرار في SharedPreferences.
- دعم RTL والعربية من البداية مع اختبار الشاشات على الهاتف والويب.
- حالات تحميل/فارغ/خطأ/انقطاع اتصال واضحة.
- لا تعتبر واجهة ثابتة أو بيانات mock ميزة مكتملة.

## قاعدة البيانات
- PostgreSQL هو المصدر الأساسي للحقيقة.
- كل تغيير بنيوي جديد عبر migration مرقمة وقابلة للتراجع حيثما أمكن؛ لا تعدّل schema الإنتاج مباشرة.
- المفاتيح الأجنبية والقيود والفهارس جزء من التصميم.
- الأموال NUMERIC وليس FLOAT، والعملة JOD بدقة 3 منازل.
- تخزين الوقت كـ timestamptz، مع تحويل العرض إلى Asia/Amman.
- لا تستخدم seed لإنشاء حساب مدير بكلمة مرور افتراضية.
- اختبارات schema وseed على قاعدة بيانات فارغة في CI.

## قواعد Git
- الفروع: `main` للإصدارات المستقرة، و`feature/*` للميزات، و`fix/*` للإصلاحات، و`docs/*` للتوثيق.
- Pull Request لكل تغيير وظيفي؛ لا دفع مباشر إلى main بعد بدء التطوير الجماعي.
- رسائل commit بصيغة Conventional Commits.
- كل PR يوضح النطاق، الاختبارات، مخاطر البيانات، وخطة الرجوع.
- لا تدمج PR مع فشل الفحوص أو مراجعة أمنية مفتوحة.

## الاختبارات المطلوبة
- Unit tests لقواعد العمل.
- Integration tests لقاعدة البيانات والمعاملات.
- E2E tests لمسارات API الحرجة.
- اختبارات عزل فروع سلبية وإيجابية.
- اختبارات تزامن للاستراحات والرقم الوظيفي.
- Flutter widget tests وintegration tests.
- اختبارات Push على أجهزة/متصفحات فعلية قبل الادعاء بدعمها.
