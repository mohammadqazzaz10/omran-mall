# سجل القرارات المعمارية (ADR)

## ADR-001: تطبيق متعدد المنصات
**القرار:** Flutter لتطبيق Android وiOS والويب، مع واجهات تتكيف مع الهاتف واللوحي وسطح المكتب.

**السبب:** قاعدة واجهات موحدة مع تجربة RTL متناسقة. يجب اختبار قدرات الويب بشكل مستقل وعدم افتراض تطابق كل خصائص الهاتف.

## ADR-002: Backend مركزي
**القرار:** NestJS + TypeScript كواجهة API مركزية، مع REST للعمليات وWebSocket للأحداث الحية.

**السبب:** تنظيم وحدات النظام، والتحقق المركزي من الهوية والصلاحيات، وإتاحة التكاملات المستقبلية.

## ADR-003: مصدر الحقيقة للبيانات
**القرار:** PostgreSQL للبيانات الدائمة والمعاملات، وRedis للكاش والطوابير والبيانات المؤقتة والمؤشرات الحية.

**قيد:** Redis ليس بديلاً عن PostgreSQL ولا يجوز أن يكون المصدر الوحيد لسجلات الحضور أو الرواتب.

## ADR-004: تعدد الفروع
**القرار:** عزل افتراضي حسب الفرع في كل طبقات الخادم وقاعدة البيانات، مع صلاحية صريحة لنطاق الشركة للإدارة العليا.

**قيد:** وجود عمود branch_id أو Guard أولي لا يكفي وحده لإثبات العزل. يلزم RLS/قيود مناسبة واختبارات وصول مباشرة وWebSocket وتقارير.

## ADR-005: الإشعارات
**القرار:** FCM لأجهزة Android والويب حيث ينطبق، وAPNs لـ iOS، وWeb Push للمتصفحات المدعومة.

**قيد:** WebSocket يستخدم للتحديث أثناء الاتصال فقط، ولا يضمن وصول إشعار والتطبيق مغلق.

## ADR-006: الملفات والوثائق
**القرار:** تخزين كائنات متوافق مع S3، وروابط موقعة مؤقتة، مع بيانات وصفية وصلاحيات في PostgreSQL.

## ADR-007: التوقيت والعملة
**القرار:** حفظ الطوابع الزمنية بتوقيت UTC عبر timestamptz، وعرضها حسب Asia/Amman. المبالغ المالية NUMERIC(12,3) بالدينار الأردني.

## ADR-008: قاعدة البيانات والترحيلات
**القرار:** المخطط الحالي مرجع أولي للمراجعة فقط. قبل اعتماده يجب تدقيق SQL، تقسيمه إلى migrations، واختباره من قاعدة فارغة مع seed آمن وقابل للتكرار.
