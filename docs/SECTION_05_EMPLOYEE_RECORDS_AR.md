# القسم 05 — الملف الوظيفي الشامل للموظف

## الهدف
توسيع الملف الوظيفي من بيانات التعريف والتعيين الأساسية إلى سجل HR منظم، مع حماية البيانات الشخصية والمالية والوثائق والعقود، والحفاظ على تاريخ الموظف عند التعديل أو النقل.

## ما نُفذ في هذه الدفعة
- إضافة صلاحيات مستقلة لعرض وإدارة البيانات الإضافية للملف، والوثائق، والعقود، والسجل الوظيفي.
- منح هذه الصلاحيات للأدوار النظامية SUPER_ADMIN وHR_MANAGER فقط؛ لا تمنح لمدير الفرع أو المشرف تلقائياً.
- إضافة API للبيانات الإضافية في `employee_profiles` مع upsert آمن، وتسجيل تدقيق مع إخفاء IBAN وأرقام الضمان/الضريبة في نسخة التدقيق.
- إضافة API لعرض بيانات الوثائق وتسجيل بياناتها الوصفية وأرشفتها منطقياً. لا يعيد API رابط الملف أو مفتاح التخزين في استجابة القائمة.
- التحقق من أن مفتاح التخزين يقع داخل مساحة الشركة/الفرع/الموظف المحددة، ومنع مسارات traversal، وتقييد MIME إلى PDF وJPEG وPNG وWebP وحجم الملف المسجل إلى 25 MiB.
- إضافة API للعقود وعرضها وإنشاء عقد حالي واحد فقط؛ يمنع إنشاء عقد حالي جديد إذا كان هناك عقد حالي قائم.
- إضافة API لسجل الموظف مع ترقيم صفحات، وتسجيل أحداث تعديل البيانات الإضافية وإضافة/أرشفة الوثائق وإنشاء العقود في `employee_history` مع إخفاء المعرفات الحساسة.
- فرض عقد حالي واحد فقط للموظف على مستوى الشركة كلها، وليس لكل فرع؛ لذلك لا يمكن فتح عقد حالي ثانٍ بعد النقل قبل إنهاء/إغلاق العقد السابق.
- التحقق في الخدمة من أن الموظف يتبع الشركة والفرع المحددين قبل أي قراءة أو كتابة.
- إضافة ترحيل 012 وفهارس للوصول إلى الوثائق والعقود والتاريخ.

## المسارات
جميع المسارات أدناه تحت:
`/branches/:branchId/employees/:employeeId/records`

| Method | Path | Permission |
|---|---|---|
| GET | `/profile` | `employee_profiles.view.branch` |
| POST | `/profile` | `employee_profiles.manage.branch` |
| GET | `/documents` | `employee_documents.view.branch` |
| POST | `/documents` | `employee_documents.manage.branch` |
| DELETE | `/documents/:documentId` | `employee_documents.manage.branch` |
| GET | `/contracts` | `employee_contracts.view.branch` |
| POST | `/contracts` | `employee_contracts.manage.branch` |
| GET | `/history?page=&limit=` | `employee_history.view.branch` |

## حدود أمنية وتشغيلية مهمة
- هذه الدفعة لا تنفذ رفع ملفات ثنائياً ولا تنشئ روابط تنزيل موقعة. حقل `storageKey` هو مرجع opaque إلى مساحة تخزين خاصة يفترض أن ينشئها تكامل S3-compatible لاحقاً؛ لا يجوز اعتباره إثباتاً أن الملف رُفع أو أن تنزيله يعمل.
- لا يعيد مسار قائمة الوثائق مفتاح التخزين، ولا يوجد مسار تنزيل عام.
- لا يجوز إرسال روابط عامة أو روابط مزود تخزين مباشرة في `storageKey`.
- لا تمنح صلاحيات العقود إلا HR_MANAGER وSUPER_ADMIN لأنها تعرض الراتب التعاقدي.
- سجل التاريخ قد يحتوي بيانات شخصية/مالية من أحداث قديمة؛ لذلك قصر عرضه على HR_MANAGER وSUPER_ADMIN.
- إنشاء عقد حالي ثانٍ للموظف مرفوض حتى تُنفذ عملية إغلاق/إنهاء عقد صريحة، حتى لو انتقل الموظف إلى فرع آخر. لا يتم إغلاق العقد القديم أو تغيير تاريخه بصمت.
- تحتفظ الوثائق والعقود بتاريخ فرعها الأصلي، لكن يمكن لموارد بشرية الفرع الحالي الوصول إلى سجل الموظف التاريخي بعد النقل؛ لا يؤدي النقل إلى إخفاء السجلات السابقة أو نقل ملكيتها التاريخية.
- أضيفت شاشة Flutter ثنائية اللغة لموارد بشرية الشركة لعرض البيانات الإضافية والوثائق والعقود والتاريخ، وتعديل البيانات الإضافية وإنشاء عقد.
- لا توجد بعد بوابة طلب تعديل بيانات من الموظف بموافقة الموارد البشرية، ولا رفع/تنزيل وثائق أو إدارة صور.

## ما بقي قبل اعتبار القسم مكتملاً
1. ربط رفع الملفات الخاص عبر S3-compatible، مع فحص نوع المحتوى والحجم، signed upload/download URLs قصيرة العمر، وحذف/احتفاظ آمن.
2. واجهات Flutter ثنائية اللغة لملف الموظف والبيانات الإضافية والوثائق والعقود والتاريخ.
3. سير موافقة لتحديث البيانات الحساسة، مع فصل التعديلات الذاتية عن تعديلات HR.
4. إجراءات دورة حياة العقود: إنهاء/تجديد/تعديل بعقد جديد وتواريخ نفاذ، ومنع التداخل.
5. إدارة الصورة الشخصية عبر التخزين الخاص والمعاينة والقص والتحقق من الصلاحية.
6. تنبيهات انتهاء الوثائق والعقود مع جدولة وإثبات وصول.
7. اختبارات تكامل PostgreSQL لعزل الفرع والموظف، واختبارات صلاحيات تمنع المدير/المشرف من رؤية IBAN والراتب والوثائق الحساسة، واختبارات API للوثائق والعقود والتاريخ.
8. اختبار واجهة Widget/E2E وتجربة المستخدم في الفرع التجريبي.

## حالة القسم
