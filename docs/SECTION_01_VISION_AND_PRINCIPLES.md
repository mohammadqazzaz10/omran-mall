# Section 01 — Vision, Objectives, and Mandatory Principles

**المراجع الملزمة:** `docs/MASTER_REQUIREMENTS_AR.md` §1 و`docs/MASTER_REQUIREMENTS_EN.md` §1  
**النطاق:** حوكمة المنتج ومعايير قبوله التي تنطبق على جميع الأقسام الأربعين.  
**القاعدة:** هذا القسم لا ينشئ شاشة أو جدولاً مستقلاً؛ نجاحه يعني أن الرؤية تحولت إلى ضوابط تنفيذ ومراجعة واختبار قابلة للإثبات. لا يجوز إعلان تحقق الرؤية النهائية قبل اكتمال نطاق المنتج كله.

## 1. الرؤية التشغيلية

إنشاء منصة مؤسسية واحدة تدير دورة حياة الموظف والعمليات اليومية والإدارية والمالية والتواصل والرقابة عبر فروع عمران مول، من إنشاء الملف الوظيفي إلى انتهاء الخدمة. يجب أن تتكامل المجالات عبر مصدر بيانات موثوق وصلاحيات موحدة وسجل تاريخي قابل للتدقيق.

النظام ليس تطبيق حضور فقط، ولا مجموعة شاشات تجريبية. كل وظيفة معلنة يجب أن تكون مدعومة بتدفق عمل حقيقي، وبيانات دائمة، وواجهات API محمية، وواجهة مستخدم مناسبة، واختبارات تثبت السلوك.

## 3. ثوابت المنتج العامة

1. اللغة الأساسية العربية مع RTL كامل، مع دعم الإنجليزية وLTR.
2. العملة JOD وتخزين المبالغ بدقة ثلاثة منازل عشرية؛ لا تستخدم floating point للأموال.
3. التوقيت المرجعي التشغيلي `Asia/Amman`، وتُستخدم ساعة الخادم للعمليات الحساسة.
4. PostgreSQL هو مصدر الحقيقة للبيانات الدائمة؛ Redis لا يستبدل السجلات الدائمة.
5. كل API وWebSocket event ومرفق وتقرير يخضع للمصادقة والصلاحية ونطاق البيانات.
6. لا تُفعل عمليات إرسال جماعي أو خصومات/أثر مالي أو نشر إنتاجي قبل الاختبارات والموافقة المطلوبة.
7. لا تُستخدم بيانات موظفين حقيقية في التطوير أو الاختبارات.
8. لا يُعلن دعم offline أو Push أو منصة أو تكامل إلا بوجود دليل اختبار يطابق الادعاء.

## 4. بوابة مراجعة إلزامية لكل تغيير

يجب أن يجيب كل Pull Request عن الآتي، مع توضيح «لا ينطبق» وسببه عند الحاجة:

- ما متطلبات القسم/الأقسام الأربعين التي يحققها التغيير؟
- هل اكتملت طبقات قاعدة البيانات وBackend وFlutter/الواجهة ذات الصلة، أم ما زالت هناك طبقات معلقة؟
- ما الهوية والصلاحية ونطاق الفرع المطلوب؟ وهل تم اختباره على الخادم؟
- هل توجد بيانات شخصية أو مالية أو ملفات أو إشعارات؟ وكيف حُميت ودُققت؟
- ما سيناريوهات النجاح والفشل وانقطاع الاتصال والتكرار؟
- ما الاختبارات التي شُغلت فعلياً، وما نتيجة CI على commit نفسه؟
- هل تتطلب التغييرات migration أو backup/restore أو rollback؟
- هل تم تحديث مصفوفة التتبع والوثائق وOpenAPI/ERD عند الحاجة؟
- هل يغيّر التغيير سلوكاً تشغيلياً أو مالياً أو قانونياً يحتاج اعتماد مالك النظام؟

## 5. تعريف إنجاز القسم الأول

يعد الإطار الحوكمي للقسم الأول جاهزاً للمراجعة عندما:
- تكون الرؤية ونطاقها وثوابتها موثقة بالعربية والإنجليزية.
- يكون لكل مبدأ معرف ثابت وضابط تنفيذي ودليل قبول محدد.
- تكون بوابة مراجعة المبادئ جزءاً من قالب Pull Request.
- ترتبط حالة القسم الأول بمصفوفة الأقسام الأربعين ولا توصف الرؤية النهائية بالمكتملة قبل إغلاق المتطلبات التشغيلية.
- تبقى كل فجوة تنفيذية ظاهرة ومصنفة ولا تتحول إلى ادعاء اكتمال.

**الحالة الحالية:** تم إعداد هذا الإطار وربطه بإجراءات مراجعة التغييرات. أما تحقق المبادئ في المنتج نفسه فما زال جارياً عبر الأقسام 2–40؛ لذلك لا يجوز وصف الرؤية النهائية للمنتج بأنها مكتملة الآن.
